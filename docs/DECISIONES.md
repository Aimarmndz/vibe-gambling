# Decisiones

Registro de las decisiones que no venían cerradas en la especificación, con su porqué. Las más recientes van al final de cada sección.

## Tooling

| Decisión                                                                                    | Por qué                                                                                                                                       |
| ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **TypeScript 6.0** (no 7.0)                                                                 | `typescript-eslint` 8.x solo admite TS `<6.1`. TS 7 (el compilador nativo) llegará cuando el linter lo soporte.                               |
| Imports con extensión `.ts` (`allowImportingTsExtensions`) y `erasableSyntaxOnly`           | El código es compatible con el _type stripping_ de Node y con cualquier bundler, sin `enum` ni sintaxis que no se pueda borrar.               |
| `packages/shared` se consume como **código fuente TS** (sin paso de build)                  | Vite, Vitest y esbuild lo transpilan solos; un paso de build más solo añadiría desincronizaciones.                                            |
| El servidor se **empaqueta con esbuild** en un único `dist/`                                | La imagen Docker no necesita TypeScript ni el código fuente de `shared`.                                                                      |
| pnpm 11 con `allowBuilds` explícito                                                         | Solo `esbuild` ejecuta scripts de instalación; las dependencias nativas opcionales de testcontainers (`ssh2`, `cpu-features`) no hacen falta. |
| Puertos locales: Postgres **5436**, servidor **8787**, GitHub falso **8788**, Vite **5173** | En la máquina de desarrollo 5432 y 5434 ya están ocupados por otros proyectos. Todos se cambian por variables de entorno.                     |

## Juego

| Decisión                                                                                                                                                                                | Por qué                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Monedas como **enteros** (`bigint` en Postgres, `number` seguro en JS) y tope de deuda `loan.maxDebt`                                                                                   | La deuda crece con interés compuesto en cada tirada; sin tope acabaría fuera de `Number.MAX_SAFE_INTEGER`.                                       |
| El interés se redondea **hacia arriba** (`Math.ceil`)                                                                                                                                   | El prestamista siempre gana: es parte del chiste y evita deudas que nunca crecen por redondeo.                                                   |
| **Boleto** (_slip_): las fichas se descuentan del saldo al ponerlas y se pueden retirar (`bet.clear`) hasta que se resuelve la ronda                                                    | Así el saldo que ve la web es siempre el disponible y no hay apuestas "sin fondos" al resolver.                                                  |
| Si no hay boleto al resolver: se repite la **última apuesta resuelta** si llega el saldo; si nunca apostó, la apuesta por defecto (10 al rojo); si no llega, la ruleta gira sin apuesta | Es la regla del plan, concretada para el caso "sin saldo".                                                                                       |
| El jackpot dev multiplica la **ganancia** (no la devolución de la apuesta)                                                                                                              | Un ×2 sobre la devolución regalaría la apuesta perdida; así es un "pago doble" honesto. Con el 0 no hay jackpot salvo que se haya apostado al 0. |
| Tríos (0-1-2, 0-2-3) y "cuatro primeros" (0-1-2-3) admitidos                                                                                                                            | Son apuestas habituales de la mesa europea; pagan como transversal (11:1) y cuadro (8:1).                                                        |
| Sin regla _la partage_: con el 0 pierden todas las sencillas                                                                                                                            | Lo pide el plan.                                                                                                                                 |
| Racha del jugador: positiva = rondas ganadas seguidas (neto > 0), negativa = perdidas; las rondas sin apuesta o con neto 0 no la rompen                                                 | Una sola cifra con signo cabe en el ranking y en el HUD.                                                                                         |
| La racha de color se calcula sobre las tiradas **del propio usuario**                                                                                                                   | Cada uno tiene su ruleta; una racha global no tendría sentido con jugadores en paralelo.                                                         |
| Temporada = identificador `AAAA-MM` del mes en que empieza; el día de cambio y la zona horaria vienen de `config/game.json`                                                             | El plan pide día 1 a las 00:00 Europe/Madrid, pero sin escribirlo en el código.                                                                  |
| Frases de humor en `packages/shared/src/i18n`, elegidas **en el cliente** sin repetir la anterior                                                                                       | Las usan la web y el mod; el servidor no necesita decidir textos.                                                                                |

## Protocolo

| Decisión                                                                                           | Por qué                                                            |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| El `device_code` de GitHub **no sale del servidor**: el mod recibe un `pollId` opaco               | Menos superficie: el mod nunca maneja nada de GitHub.              |
| `/bet` desde el mod manda la casilla **como texto** y el servidor la interpreta (`parseBetTarget`) | El mod no puede importar zod ni `shared`; así hay un único parser. |
| Errores HTTP con cuerpo `{ v, error, message }` y códigos de `ERROR_CODES`                         | Un único formato para el mod y la web.                             |

## Mod

| Decisión                                                                                                                                                                                                                                                                                          | Por qué                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| La tirada se dispara en `turn.start` (no en `prompt.submit`) y se cierra en `turn.complete` sin `agentId`                                                                                                                                                                                         | `turn.start` solo existe en el bucle principal (los subagentes no lo lanzan) y trae el texto ya asentado; `turn.complete` de un subagente lleva `agentId` y se ignora. Un turno sin texto (continuación del engine) no es una tirada.                                                  |
| `turnId` propio (`crypto.randomUUID()`), nunca el del engine                                                                                                                                                                                                                                      | El id del engine no sale del ordenador; el del mod sirve para la idempotencia.                                                                                                                                                                                                         |
| Todo `$` vive en `hooks/register.ts`, adaptado a una interfaz `Io` (`hooks/lib/io.ts`)                                                                                                                                                                                                            | El engine solo deja usar `$` en el archivo del hook (`claude plugin validate` lo rechaza si cruza un import). Así `hooks/lib` es TypeScript puro: se prueba sin engine y `shared` puede importar los constructores de payload.                                                         |
| Red siempre en segundo plano con timeout de `$.clock.after` (≤ 1,5 s en el turno)                                                                                                                                                                                                                 | El entorno del mod no tiene `setTimeout` y `$.http.fetch` no acepta señal; los hooks del turno vuelven al instante y llaman a `next(e)`.                                                                                                                                               |
| En `claude -p`, `turn.complete` espera el envío de `turn/end` como mucho `turnTimeoutMs` en total y no abre ninguna ventana                                                                                                                                                                       | El proceso termina con el turno y se perdería la tirada, pero un turno nunca espera más de 1,5 s al casino aunque `turn/start` siga en vuelo; en `-p` no hay nadie mirando (ni toast ni ventana: tampoco en el E2E o en el CI). En sesión interactiva no se espera nada.               |
| El toast del resultado se programa para `revealAt − resolvedAt` (máx. `revealMaxDelayMs`) y la status line se actualiza a la vez                                                                                                                                                                  | No destripar el resultado antes de que lo enseñe la ventana; se mide con los dos instantes del servidor para no depender del reloj local.                                                                                                                                              |
| Detección de `git push`: solo cuenta si el push va en la línea y todo lo que sigue va con `&&`; no cuenta `--dry-run`, ni "Everything up-to-date"                                                                                                                                                 | El código de salida es el de la línea entera; un push que no sube nada no es "push to prod". El comando y su salida se miran en local y se olvidan.                                                                                                                                    |
| Test fallido = comando de tests conocido (npm/pnpm/yarn/bun test, vitest, jest, pytest, go/cargo/dotnet/mvn/gradle test, playwright, `claude plugin test`…) que termina con error                                                                                                                 | Heurística sencilla y predecible; los falsos negativos solo quitan una frase de consuelo.                                                                                                                                                                                              |
| Ventana: `sh -c '"$@" &'` en Linux, `open -na App --args` en macOS, `cmd /d /c start "vibe gambling" …` en Windows                                                                                                                                                                                | `$.process.run` espera a que el proceso acabe: el lanzador tiene que volver al momento y dejar el navegador vivo. Los argumentos van por posición (sin interpretar). En Windows el título lleva un espacio para que vaya entre comillas (con `""` literal el escape de argv lo rompe). |
| Solo se abre la URL del enlace si es http(s), del mismo origen que `serverUrl` y sin metacaracteres                                                                                                                                                                                               | Un servidor (self-host) no puede hacer que el mod abra otra cosa ni inyectar opciones al navegador.                                                                                                                                                                                    |
| "Una sola vez": tras abrir, no se vuelve a abrir hasta `windowReopenCooldownMs` salvo que la ventana conecte (`windowConnected`) o se use `/roulette`                                                                                                                                             | Evita ventanas duplicadas mientras la primera arranca.                                                                                                                                                                                                                                 |
| `/vibe-server` guarda la URL con `$.config.set` en la opción `serverUrl` (y `default` vuelve al valor del manifiesto)                                                                                                                                                                             | Una sola fuente de verdad, visible en `/config`; el engine recarga el mod con la nueva opción. Antes comprueba `GET /api/meta` (protocolo igual al del mod).                                                                                                                           |
| Token en `$.store` con clave por servidor (`session:<serverUrl>`)                                                                                                                                                                                                                                 | Cambiar de servidor no mezcla sesiones y volver al anterior conserva el login.                                                                                                                                                                                                         |
| SO: `OS=Windows_NT` → `win32`; si no, `uname -s`                                                                                                                                                                                                                                                  | No hay `process.platform` en el entorno del mod.                                                                                                                                                                                                                                       |
| Idioma: opción `language` (`auto` por defecto) → `LC_ALL`, `LC_MESSAGES`, `LANG`, `LANGUAGE`                                                                                                                                                                                                      | El plan pide el idioma del sistema; en Windows sin esas variables queda en inglés.                                                                                                                                                                                                     |
| Opciones no válidas → el mod no hace nada, status "🎰 bad config" y los comandos explican el error                                                                                                                                                                                                | Nunca se inventa un valor (regla de `CLAUDE.md`).                                                                                                                                                                                                                                      |
| Copia generada de `shared` en `hooks/generated/` (`pnpm sync:mod`); `packages/shared/test/mod-contract.test.ts` falla si está desactualizada y valida los cuerpos del mod con zod                                                                                                                 | El mod se instala solo (`packages/mod`) y no puede importar `shared` ni zod.                                                                                                                                                                                                           |
| Rutas de la API en `shared` (`API_ROUTES`, aditivo)                                                                                                                                                                                                                                               | Una única fuente de verdad para servidor, web y mod.                                                                                                                                                                                                                                   |
| Tipos del engine sin versionar; `scripts/mod-engine-types.ts` los genera con el `claude` instalado (`CLAUDE_CODE_PLUGIN_DIR_WATCH=1 claude -p /balance --plugin-dir packages/mod`, con configuración temporal y sin API key)                                                                      | Son de Anthropic y van ligados a la versión de Claude Code; así el `typecheck` funciona igual en local y en el CI (que instala la misma versión).                                                                                                                                      |
| Comandos registrados con nombre literal y sin spread en `$.command.register`                                                                                                                                                                                                                      | Así `claude plugin validate` reconoce que el módulo responde sus propios comandos (no son "gating hooks").                                                                                                                                                                             |
| La ventana se abre en segundo plano: `turn/end` nunca espera al enlace ni al lanzador del navegador; `uname` va con el timeout del turno                                                                                                                                                          | Antes la apertura (enlace + lanzador, hasta `launchTimeoutMs`) colgaba de la promesa de `turn/start` y retrasaba el cierre de la ronda.                                                                                                                                                |
| Rangos de las opciones numéricas en el `userConfig` del manifiesto (`min`/`max`); el código solo comprueba el tipo y la regla de oro (`turnTimeoutMs` ≤ 1500)                                                                                                                                     | Nada hardcodeado: el engine valida los rangos antes de cargar el mod y dice qué opción falla.                                                                                                                                                                                          |
| `serverUrl` (opción y `/vibe-server`): https, o http solo hacia esta máquina (`localhost`, `*.localhost`, `127.0.0.0/8`, `[::1]`); host solo con caracteres de dominio o IP                                                                                                                       | Con http el token de sesión viaja en claro, y la cookie `Secure` de la web tampoco funcionaría fuera de localhost.                                                                                                                                                                     |
| Texto del servidor (código y URL del Device Flow, login, nombre del servidor, mensajes de error) limpio de caracteres de control, secuencias ANSI/OSC y marcas bidi, y cortado a `TEXT_LIMITS` (aditivo en `shared`)                                                                              | Un servidor self-host comprometido no puede borrar la pantalla, disfrazar enlaces ni escribir en el portapapeles (OSC 52). La URL de verificación tiene que ser http(s).                                                                                                               |
| Device Flow: un 4xx en el polling (salvo 408/429) corta el login con un toast; 5xx, 429 y fallos de red se reintentan; la siguiente consulta nunca va más allá de la caducidad del código; dos `/vibe-login` a la vez comparten la misma petición                                                 | Que el login no se quede consultando en silencio hasta caducar, que el aviso de "caducado" llegue a su hora con cualquier intervalo y que no se enseñen dos códigos.                                                                                                                   |
| Windows: si la ruta del navegador tiene metacaracteres de `cmd` (`&\|<>^%"!`), se abre el navegador por defecto                                                                                                                                                                                   | La ruta sale de variables de entorno (el nombre del usuario) y el argv solo va entre comillas si hay espacios; `cmd` la interpretaría.                                                                                                                                                 |
| Una orden de Bash en segundo plano (`backgroundTaskId`) no cuenta como push ni como test; `--help`/`-h`/`-n` agrupado no son un push; se miran envoltorios (`timeout`, `sudo -u`, `nice -n`), subshells y lanzadores (`pnpm vitest`, `pnpm exec`, `uv run`, `poetry run`, `bundle exec`, `npm t`) | Menos falsos positivos y negativos sin guardar nada más que los dos booleanos.                                                                                                                                                                                                         |
| `/bet`: separador de miles solo en grupos de tres (`1.000`, `1,000`, `1_000`); `1.5` es un error                                                                                                                                                                                                  | Antes `1.5` se leía como 15 monedas.                                                                                                                                                                                                                                                   |
| Cada `$.command.register` va por separado (un rechazo se registra en el log) y `/roulette` explica el fallo real del enlace (sesión caducada, servidor caído)                                                                                                                                     | Un nombre ocupado no deja sin comandos ni sin status line; "¿hay un navegador?" no era la respuesta a un 401.                                                                                                                                                                          |

## Servidor

| Decisión                                                                                                                                                                                                                                        | Por qué                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Todas las variables de entorno son **obligatorias** (sin valores por defecto en el código); `config.ts` es el único módulo que lee `process.env` y lista de golpe todo lo que falta                                                             | "Nunca arranca con un valor inventado". Desarrollo usa `deploy/dev.env`, los tests `test/helpers/env.ts` y producción `deploy/.env`.                                                                                                                                                                                                          |
| `siteConfigSchema` = `webConfigSchema.shape.site`                                                                                                                                                                                               | Coherente por construcción con `/config.json`: no hay dos esquemas que puedan divergir.                                                                                                                                                                                                                                                       |
| Rutas, métodos y quién puede llamar a cada una salen de `API_ROUTES` (shared); además se aceptan `PATCH /api/me/settings` y `DELETE /api/me` como alias REST                                                                                    | Una sola fuente de verdad para servidor, web y mod. Las rutas `mod` exigen `Bearer` de una sesión de mod y las `any` aceptan también la cookie web; una sesión web en `Bearer` (o una de mod en cookie) recibe 403.                                                                                                                           |
| Serializador de respuestas propio (`safeParse` + `JSON.stringify`) en vez del de `fastify-type-provider-zod`                                                                                                                                    | El de la librería usa `encode`, que no admite las transformaciones de los esquemas de `shared` (ordenar los números de una apuesta). Toda respuesta 200 se valida contra su esquema.                                                                                                                                                          |
| **Cerrojo de dinero = fila de la cartera de la temporada** (`SELECT … FOR UPDATE` tras un `INSERT … ON CONFLICT DO NOTHING`) en toda operación de dinero y de rondas                                                                            | Serializa todo lo que hace un usuario sin bloquear a los demás. Probado con 150 apuestas simultáneas (entran exactamente 100) y con mezclas de apuestas, retiradas, préstamos y resoluciones.                                                                                                                                                 |
| El **boleto** vive en `wallets.slip` (jsonb) y la última apuesta en `users.last_bets`                                                                                                                                                           | El boleto queda protegido por el mismo cerrojo que el saldo; la apuesta a repetir sobrevive al cambio de temporada.                                                                                                                                                                                                                           |
| Una sola ronda abierta por usuario, garantizada además por un índice único parcial (`WHERE status = 'open'`)                                                                                                                                    | Defensa en profundidad si alguna vez se tocara una ronda sin el cerrojo.                                                                                                                                                                                                                                                                      |
| Idempotencia con la tabla `turns` (clave `(user_id, turn_id)`); la ronda guarda `resolved_by_turn_id`                                                                                                                                           | El reintento de un `turn/end` devuelve la misma ronda resuelta; el `turn/end` de la otra sesión que compartía ronda devuelve `no_round`.                                                                                                                                                                                                      |
| Un `turn/end` sin `turn/start` previo (se perdió por red o timeout del mod) abre y resuelve la ronda en el acto (manda `round.started` y `round.resolved`)                                                                                      | Cada prompt es una tirada aunque falle la primera llamada.                                                                                                                                                                                                                                                                                    |
| Ronda caducada (más de `round.staleAfterMs` o de una temporada ya vencida) = `expired`, sin tirada; se detecta de forma perezosa y en el cierre de temporada, y se avisa con `round.expired`                                                    | No hace falta otro job; las fichas del boleto siguen en la cartera, así que caducar no pierde dinero.                                                                                                                                                                                                                                         |
| El interés de la deuda se cobra en cada tirada **resuelta** (también si la ronda no lleva apuesta)                                                                                                                                              | "La deuda crece un % fijo por cada tirada".                                                                                                                                                                                                                                                                                                   |
| El préstamo se concede si `saldo + boleto` no llega a la ficha mínima                                                                                                                                                                           | Si no contara el boleto, bastaría con apostarlo todo, pedir el préstamo y retirar las fichas.                                                                                                                                                                                                                                                 |
| `/api/bet` y `bet.place` aceptan cualquier cantidad ≥ ficha mínima (no solo los valores de las fichas); `all-in` = todo el saldo disponible (aunque sea menor que la ficha mínima)                                                              | `/bet 200 red` tiene que funcionar; el all-in de lo último que queda es parte del chiste.                                                                                                                                                                                                                                                     |
| `colorStreak` se devuelve siempre (color y cuenta al final de las últimas `streak.historySize` tiradas del usuario); la web decide cuándo avisar con `colorWarningAt`                                                                           | El dato es útil aunque no llegue al umbral, y el umbral ya va en `/config.json`.                                                                                                                                                                                                                                                              |
| Device Flow: el poll se "reclama" con un `UPDATE … WHERE last_polled_at <= now − intervalo + DEVICE_POLL_LEEWAY_MS`; si llega antes, se responde `pending` sin preguntar a GitHub                                                               | Dos polls simultáneos o un mod impaciente nunca provocan un `slow_down` de GitHub. Con `slow_down` se guarda el intervalo nuevo (el que diga GitHub o +5 s).                                                                                                                                                                                  |
| El token de GitHub solo existe dentro de `devicePoll` (pedir `/user` y olvidarlo); del perfil solo se guardan id, login y avatar                                                                                                                | Lo pide el plan; un test vuelca las tablas y comprueba que el token no está en ninguna.                                                                                                                                                                                                                                                       |
